# M77 6306: both sides and the stacked-arch sign

The original catalogue records **two eight-token fields** for 6306. The existing
candidate export preserves the first field only. The second field has now been
transcribed from *Texts*, printed page 148 / PDF page 159, and checked against its
repeated presentation in the concordance. The printed metadata keeps the fields
on separate sides; they must not be concatenated as one text line.

| Side / line | Printed metadata | Normalized right-to-left reading order |
|---|---|---|
| 1 / 0 | 610001 | M109 M059 M367 M380 M314 M106 M018 M162 |
| 2 / 0 | 20001, inheriting object type 6 | *M129 M287 M086 M065 M067 M403 M087 M342 |

The asterisk on **M129** is the catalogue's doubtful-reading mark. No other doubt
mark or loss span appears in these two fields. Both sides have direction code 1,
no field symbol and one line. Object code 6 means bronze implement in this
catalogue; this is not a new compositional analysis of its metal.

![Both fields and their metadata](../results/primary_pages/c40-catalogue-6306-detail.png)

The initial identification of the hourglass-like counterpart glyph was uncertain
during review. Its numbered sign-list form and the concordance index on printed
246 / PDF 257 resolve it as **M067**. The reading is not M002 or M008. The
counterpart's tentative alternatives were not promoted to the ledger. The
concordance also reproduces the capped M065 beside it and preserves the M129 doubt.

Appendix V, printed page 825 / PDF page 834, joins 6306 to **CE plate LXXIV item 1**.
This is the catalogue's source join. Physical photographs, the CISI C-40 identity,
and original crossed layout are being examined separately; normalized catalogue
layout cannot authenticate how incision groups intersected on the original object.

## Three arches are one catalogue sign

The numbered sign list, printed 34 / PDF 45, distinguishes M312 (one arch),
M313 (two vertically stacked arches), and M314 (three vertically stacked arches).
Each has its own catalogue identifier. M314 occupies one position in the eight-token
first field of 6306, directly followed in normalized reading order by the
five-stroke group M106.

![Numbered one-, two- and three-arch forms](../results/primary_pages/c40-signs-312-314.png)

This is evidence for graphic grouping, not an equation `M314 = 3 × M312`.
Neither three M312 tokens nor five unit-code tokens are added to the transcription.
The interpretation `3u 5i` requires additional claims about composition and
values. The primary M77 row has no doubt mark on M106, whereas a later author's
uncertainty about the five-stroke reading concerns the source interpretation;
these different assessments should both be retained without silently harmonizing them.

## Complete bounded inventory of M312–M314 in this catalogue

The contiguous concordance sections on printed 556–557 / PDF 567–568 give five
indexed occurrences. Their counts and positions agree with Table I, printed 721 /
PDF 732, which was also visually checked:

| Code | Reference, side, line | Indexed field in normalized reading order | Position |
|---|---|---|---|
| M312 | 4802, 0, 0 | *M312 M102 | Initial, doubtful M312 |
| M312 | 2923, 2, 0 | M387 M015 M104 M106 M312 | Final |
| M313 | 4804, 0, 0 | M313 M102 | Initial |
| M313 | 8302, 2, 0 | M313 | Solus |
| M314 | 6306, 1, 0 | M109 M059 M367 M380 M314 M106 M018 M162 | Medial |

Thus the catalogue totals are 2, 2 and 1 respectively. Other arch codes, including
M315 and higher, are outside this bounded inventory. This is an accounting of
M77's indexed occurrences, not all ancient examples or five independent numerical
measurements. The 4802/4804 pair shares the short-stroke context M102, but the
single-arch member is explicitly doubtful. It cannot be treated as an entirely
clear minimal pair. The 2923 and 8302 auxiliary fields also show why one-field
exports undercount this selected three-code group. This audit does not add duplicate copies of fields
already recovered in prior phases.

The new 6306 counterpart contains none of M312–M314. Recovering it improves full
object coverage without increasing the selected codes’ totals. Its eight tokens remain one
separate, partly doubtful field.
