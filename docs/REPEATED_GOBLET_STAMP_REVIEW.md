# Conditional counterexample: repeated goblet stamp

The first paragraph of Vats, *Excavations at Harappā* (1940), volume I, printed p.91, explicitly reports that trough **470**, in square **M12/13**, contained **two goblets with pointed bases, each stamped with the same seal**. It cites **Plate CII,21**. I independently checked the retained page image, `data/raw/capacity-context-vats-leaf117.jpg`; the wording is legible and unambiguous. The suggestion that the stamp might be the potter's name is the author's conjecture, not an established reading.

If that report accurately describes two distinct physical goblets bearing the same stamp design, then **that design alone cannot uniquely identify each individual physical vessel**: for goblets A and B, A≠B but design(A)=design(B). This is a conditional historical counterexample to that narrowly defined universal claim, not a statistical test or an independent physical inspection of both goblets.

The observation does not exclude an owner, maker, workshop, batch or class identifier; a reused label; or a unique vessel identifier composed of this stamp **plus additional distinguishing information**. It says nothing about whether other, unreported marks differentiated the goblets. Accidental differences between impressions are also distinct from the shared stamp design. No semantic or phonetic reading follows from repetition.

The trough's number is not a separate excavation number for either goblet. This review assigns neither goblet a field number, CISI alias or M77 text. A later paragraph on the same page mentions goblet 3262 and repeats Plate CII,21, but that shared illustration reference alone does not establish that 3262 was one of the two goblets in trough 470. Plates were not inspected because the reported two-object repetition is explicit; actual design identity remains conditional on the report.

`scripts/persist_repeated_goblet_stamp_review.py` preserves the first-paragraph crop, this review and the source hash in `data/processed/repeated_goblet_stamp_review.json`. No new source bytes were downloaded. No semantic or phonetic values were assigned; all 417 values remain null.
